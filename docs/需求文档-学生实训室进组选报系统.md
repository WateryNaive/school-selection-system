# 学生实训室进组选报系统 · 需求文档

> 版本：v0.2（关键决策已定，见第十节）
> 形态：网页版（学生 / 导师 / 管理员均用浏览器访问）
> 账号：系统内管理（管理员导入名单，学号或工号 + 初始密码登录）
> 通知：站内信 + 钉钉
> 日期：2026-11-09 

***

## 一、这个系统要解决什么

学院每年要把学生分配进各个实训室做 AI+PBL 项目实训。整个过程不是"学生报个名就完事"，而是一套**双向选择 + 分轮录取 + 统筹调剂**的流程：学生挑导师，导师也挑学生；一轮没录上还有补录；最后剩下的名额和学生由学院统一调剂兜底。

线下靠 Excel 和微信群跑这套流程，最容易出乱子的地方是：名额算错、有人被重复录取、确认超时没人盯着、调剂顺序说不清、结果不好追溯。这个系统就是把海报上那 8 个阶段搬到线上，让**名额、状态、时间窗口、录取顺序**都由系统自动管住，人只做该做的决策（面试打分、选去向、调剂安置）。

### 本届规模（已确认）

- 学生：约 **380** 人 / 届
- 实训室：**7** 个
- 导师：每室 5 名，共 **35** 名
- 名额：每名导师约 12 人 → 每室约 60 人 → **总容量约 420 个**

总容量 420 > 学生 380，多出约 40 个（约 10% 余量）。这意味着**名额总量够，人人理论上都有位置**——流程的真正难点不是"抢有限名额"，而是把偏好匹配公平：热门实训室 / 导师会挤爆、冷门的招不满，再靠三轮补录和统筹调剂兜底，让服从调剂的学生基本都能入组。最终仍无去向的，只会是极少数不服从任何调剂、约谈后仍无法安置的学生。

### 三个核心机制

后面所有规则都围绕它们：

- **双向选择**：学生填意向、导师面试打分，双方都认可才算数。学生可以拿到多个拟录取，但最后只能去一个。
- **分轮录取**：第一轮没录上的学生，还有第二轮、第三轮补录机会，每轮重新填志愿、重新面试确认。
- **统筹调剂**：三轮之后还有空名额和没着落的学生，进入全院调剂池，按"室内调剂 → 跨室调剂 → 约谈安置"三级优先级兜底。

### 名词约定

| 名词      | 含义                                        |
| ------- | ----------------------------------------- |
| 实训室     | 招生的基本单位，有总名额、项目方向、培养安排。本届每室 5 名导师。        |
| 导师      | 学生填报志愿的对象，隶属于某个实训室，本届每人带教容量约 12。          |
| 意向 / 志愿 | 学生对某个导师的一次报名。首轮最多 3 个，且**平行、不分先后**。       |
| 室内调剂    | 把学生从所报导师调到**同一实训室**的其他导师 / 方向。            |
| 跨室调剂    | 把学生调到**其他实训室**。                           |
| 拟录取     | 导师 / 实训室初选出的意向录取名单，还没最终生效，要等学生确认。         |
| 递补      | 名额空出时，按顺位从候补名单里补人。                        |
| 轮次      | 首轮 + 第二轮补录 + 第三轮补录，每轮是一套完整的"填报—面试—确认—递补"。 |

## 二、角色与权限

系统里主要有四类角色（系统管理员可与学院管理员合并）：

- **学生**：看宣讲 / 实训室信息、填意向、查自己的面试与录取状态、确认去向、补录重填、看公示、提异议。只能看和操作自己的数据。
- **导师**：看报考自己（或本实训室）的学生、参与面试打分、提交拟录取 / 递补 / 内部调剂候选建议。只能看本实训室相关数据。
- **实训室负责人**：以实训室为单位统筹面试、汇总并提交本室的拟录取 / 递补 / 内部调剂候选名单、管理本室名额分配。通常由一名导师兼任。
- **学院管理员**：管理基础数据与账号、设置并控制各阶段时间窗口、公布剩余名额、发起并执行统筹调剂、汇总公示、处理异议、导出各类名单。全局权限。

| 功能                    |  学生  |  导师  | 实训室负责人 |  学院管理员  |
| --------------------- | :--: | :--: | :----: | :-----: |
| 查看宣讲 / 实训室介绍          |   ✓  |   ✓  |    ✓   |    ✓    |
| 填报 / 修改意向             |   ✓  |   —  |    —   |  代操作\*  |
| 面试打分                  |   —  |   ✓  |    ✓   |    —    |
| 提交本室拟录取 / 递补 / 调剂候选名单 |   —  |  建议  |    ✓   | 审核 / 兜底 |
| 确认录取去向                |   ✓  |   —  |    —   |  代操作\*  |
| 公布剩余名额、开启补录           |   —  |   —  |    —   |    ✓    |
| 执行统筹调剂                |   —  |   —  |  室内建议  |    ✓    |
| 汇总公示、处理异议             |  提异议 |   —  |    —   |    ✓    |
| 账号 / 基础数据 / 时间窗口配置    |   —  |   —  |    —   |    ✓    |
| 数据导出                  | 个人结果 | 本室名单 |  本室名单  |    全部   |

\* "代操作"指管理员在特殊情况（如学生线下申请）下可留痕代办，非默认流程。

## 三、整体流程与时间轴

海报里的 8 个阶段，串起来是这样一条主线：

```
宣讲 → 开放日 → 意向填报 → 面试初选 → 拟录取确认
                                          │
                                ┌─────────┴─────────┐
                              已录取              未录取
                                │                   │
                                │            第2轮补录 → 第3轮补录
                                │                   │
                                │              仍未录取
                                │                   │
                                │             统筹调剂（三级优先级）
                                └─────────┬─────────┘
                                          │
                                    结果公示（1天）→ 正式入组
```

### 示例时间轴

下面是海报给出的时间安排，作为**示例**。系统里所有时间点都做成**可配置**，每年 / 每届可改，不写死。

| 阶段 | 名称          | 示例时间                      | 时间窗口性质              |
| -- | ----------- | ------------------------- | ------------------- |
| 1  | 集中宣讲        | 10月29日 14:00              | 信息发布，长期可见           |
| 2  | 实训室开放日      | 10月29日 — 10月30日           | 信息展示                |
| 3  | 意向填报        | 11月2日 08:00 — 12:00       | **硬窗口**，到点开放 / 关闭   |
| 4  | 导师初选与面试考核   | 11月2日 12:00 — 11月3日 17:00 | 导师录入窗口              |
| 5  | 拟录取与学生确认    | 11月4日 08:00 — 12:00       | **硬窗口**，逾期视为放弃      |
| 6  | 分轮补录（第2、3轮） | 11月4日 12:00 — 11月5日 17:00 | 每轮内含填报 / 面试 / 确认子窗口 |
| 7  | 统筹调剂录取      | 11月6日 08:00 — 12:00       | 管理员操作窗口             |
| 8  | 结果公示与正式入组   | 公示 1 天                    | 公示倒计时               |

### 阶段状态

每个阶段有统一的状态：`未开始 → 进行中 → 已关闭`。系统按**服务器时间**自动切换，管理员也可手动强制开启 / 关闭（留痕）。学生的可操作项严格跟随当前阶段状态，杜绝提前填报、超时确认。

## 四、分阶段功能需求

### 4.0 支撑模块（贯穿全程）

- **账号与登录**：管理员批量导入学生名单（学号、姓名、班级 / 专业、联系方式、钉钉 userid）和导师名单（工号、姓名、所属实训室、钉钉 userid）。学号 / 工号 + 初始密码登录；**初始密码 = 固定前缀 + 学号后 6 位**（每人不同，告知规则即可发放），**首次登录强制改密**，导师用工号同理。
- **基础数据管理**：维护实训室（名称、介绍、项目方向、总名额、培养安排、考核要求、负责人）、导师（研究方向、带教容量，本届默认约 12）、学生名单。
- **通知 / 消息**：**站内信（必做）+ 钉钉**。关键节点定向推送，例如"填报即将截止""你收到 2 个拟录取，请在 X 点前确认""补录开始，请重新填报""公示已发布"。
  - **钉钉对接**：定向个人通知走钉钉"工作通知"接口（需企业内部应用凭证 + 学生 / 导师钉钉 userid 映射）；群播报可用**群机器人 webhook** 作为补充或起步方案。所需凭证与人员映射见文末"对接依赖清单"。
- **审计日志**：评分、录取、确认、递补、调剂、公示等关键动作全程留痕（谁、何时、对谁、做了什么），可追溯、可导出。
- **统计与导出**：各阶段名单、报名 / 录取 / 未录取统计、名额使用率，一键导出 Excel。

### 4.1 阶段一 · 集中宣讲

- 管理员发布宣讲信息（时间、地点、参与实训室），各实训室展示项目方向、招录名额、培养安排、考核要求。
- 学生可浏览全部实训室 / 导师的介绍页。
- **v1 纯信息展示**，宣讲报名 / 签到不做，后续有需要再加。

### 4.2 阶段二 · 实训室开放日

- 展示各实训室开放日安排（时间、地点、联系人）。
- 学生浏览实训室详情、导师方向、往届项目等信息，为填报做准备。
- **v1 纯信息展示**，走访预约 / 意向登记不做。

### 4.3 阶段三 · 意向填报

- 在硬窗口内（示例 11月2日 08:00—12:00），学生填报**最多 3 个平行导师意向**。
- **三个意向完全平行、不分先后**，系统不得按填报顺序赋予优先级。
- 同时提交两个调剂意愿开关：
  - 是否服从**实训室内部调剂**；
  - 是否服从**全院跨实训室调剂**。
- 窗口内可反复修改，窗口关闭即锁定。截止后不可再改。
- 校验：意向不超过 3 个、不可重复报同一导师、必须在窗口内提交。
- 未填报的学生视为放弃本轮，管理员可查看未填报名单并提醒。

### 4.4 阶段四 · 导师初选与面试考核

- **以实训室为单位统一组织面试**：凡报考该实训室的学生**全部进入面试**，无论报名是否满额。
- 面试打分四个维度：**学习态度、逻辑思维、编程基础、时间投入**。每维 **0–25 分、满分 100，默认等权**（权重后台可配置）；建议 **2–3 名评委各打一份取平均**（可选去掉最高最低），减少单人偏差，嫌重也可默认录一份汇总分。"时间投入"可先让学生填每周可投入小时数，评委据此打分。系统自动算总分、生成本室排名。
- 实训室负责人 / 导师据此产出三份名单：
  - **拟录取名单**：按名额和排名初选，映射到具体导师；
  - **递补名单**：候补，**带明确顺位**；
  - **内部调剂候选名单**：本室想要、但所报导师放不下、可调到本室其他导师的学生。
- 一个学生可能同时被多个实训室 / 导师列入拟录取（因为志愿平行），这种情况留到阶段五处理。
- 评分与名单提交后锁定，修改需留痕 / 版本记录。

### 4.5 阶段五 · 拟录取与学生确认

在硬窗口内（示例 11月4日 08:00—12:00）处理确认：

- **只收到 1 个拟录取** → 系统**自动确认**，占用该名额。
- **收到 2 个及以上拟录取** → 学生在窗口内**自主选择唯一去向**；选定后，其余拟录取名额**立即释放**。
- **逾期未确认** → **视为放弃全部拟录取**，释放其占用的所有名额。
- 释放出的名额 → 按**递补顺位**补人：
  - 递补对象必须是**当前仍未录取**的学生；
  - 顺位靠前者若已在别处确认，跳过、顺延下一位；
  - **递补默认直接生效并通知**（补进去的本就是该生填过的平行志愿之一，属于已表达意愿），不再单独确认；
  - 递补可能再触发新的释放 / 递补，级联循环直到无名额可补或无合格候补（详见第五节）。
- 确认结果实时反映到名额占用看板，管理员可监控确认进度、对未确认学生一键提醒（站内信 + 钉钉）。

### 4.6 阶段六 · 分轮补录（第 2、3 轮）

- 管理员**公布剩余名额**（哪些实训室 / 导师还有空位）。
- **仅未录取学生**可重新填报志愿（规则同首轮：最多 3 个平行意向 + 调剂意愿）。
- 实训室统一组织面试、双向确认、顺位递补，流程与首轮一致。
- **依次完成第二轮、第三轮**：每轮结束才进入下一轮；每轮只涉及仍未录取的学生和仍有空余的名额。
- 每轮内部同样有填报 / 面试 / 确认的子时间窗口，由管理员配置。

### 4.7 阶段七 · 统筹调剂录取

三轮补录后仍剩余的名额纳入**全院调剂池**，对仍未录取的学生按优先级统筹安排：

1. **第一优先级 · 实训室内部调剂**：把服从室内调剂、且具备本室调剂候选资格的学生，安置到本室剩余名额。
2. **第二优先级 · 全院跨实训室调剂**：把服从跨室调剂的学生，安置到全院任意剩余名额。
3. **第三优先级 · 约谈与最终安置**：对**未服从调剂**的学生，由学院约谈后做最终统筹安置（人工决策，系统记录结果）。

- **调剂不再面试**，直接按学生**原面试总分 + 调剂意愿**统筹；同一优先级内按原面试总分从高到低排序匹配。
- 系统提供调剂工作台：展示剩余名额池、待调剂学生（含调剂意愿、面试分、候选来源），支持自动预分配 + 人工调整，确认后生效。
- 调剂全程留痕，安置结果可导出。

### 4.8 阶段八 · 结果公示与正式入组

- 学院汇总最终录取名单并**公示，公示期 1 天**（可配置），系统显示公示倒计时。
- 公示期内学生可**提出异议**：**学院管理员（教务）受理**，在公示结束后 **24 小时内**处理并通过站内信 + 钉钉反馈；异议成立则**留痕改判**、对受影响部分重新公示。
- 公示无异议后，名单生效，学生状态置为**正式入组**，进入 AI+PBL 项目实训。
- 导出最终录取总表（学生、实训室、导师、录取轮次 / 方式）。

## 五、核心业务规则与算法

这一节把最容易算错、扯皮的逻辑定死，供开发直接落地。

### 5.1 志愿填报

- 每轮每生最多 3 个意向，平行无先后；不可重复报同一导师。
- 两个调剂意愿开关独立：服从室内调剂、服从跨室调剂。
- 只有硬窗口内可提交 / 修改，关闭即锁定。

### 5.2 评分与排名

- 四维打分（学习态度、逻辑思维、编程基础、时间投入），每维 0–25、加权总分 100，默认等权（可配置）；多评委取平均。
- **并列顺位链（确定性、可复算）**：总分相同 → 依次比 **逻辑思维 → 编程基础 → 学习态度 → 时间投入** → 仍相同按 **学号升序** 兜底。不使用随机抽签，保证可追溯。

### 5.3 拟录取生成

- 每个实训室按名额上限，从高分到低分生成拟录取，映射到导师容量（导师约 12 / 人，实训室约 60 / 室为硬上限）。
- 超出名额但本室仍想要的 → 递补名单（带顺位）或内部调剂候选名单。

### 5.4 多意向确认与递补（含级联）

- 学生对"拟录取集合"做处理：1 个自动确认；≥2 个择一确认，释放其余；**逾期释放全部**。
- 释放名额触发递补：
  - 递补只发给**当前未录取**学生；
  - 顺位靠前的候补若已在别处录取，跳过、顺延；
  - **递补直接生效并通知**，不再单独确认；
  - 递补占用名额、可能再触发新的释放 / 递补，**循环直到无名额可补或无合格候补**。

### 5.5 分轮补录循环

- 每轮：公布剩余名额 → 未录取学生重填 → 面试打分 → 拟录取 → 确认 → 递补。
- 轮次严格串行，第 2 轮结束才开第 3 轮；已录取学生退出后续轮次。

### 5.6 统筹调剂三级优先级

- 严格按"室内调剂 → 跨室调剂 → 约谈安置"顺序执行，前一级用掉的名额 / 学生不进入后一级重复分配。
- 每级只在"剩余名额"和"仍未录取且符合该级条件的学生"之间做匹配，**同级内按原面试总分排序，不再面试**。
- 第三级为人工约谈安置，系统只记录最终结果。

### 5.7 名额与一致性（关键）

- 任何录取 / 确认 / 递补 / 调剂都涉及名额扣减，**必须用事务保证原子性**，杜绝并发下的超额录取。
- 名额占用、释放、再占用要有清晰流水，任意时刻"已占用名额 ≤ 总名额"恒成立（导师 ≤ 约 12、实训室 ≤ 约 60）。
- 录取结果一旦生效即锁定，回退 / 改判需管理员操作并留痕。

## 七、学生状态流转

一名学生的完整旅程（总状态）：

```
未填报
  → 已填报待面试
  → 面试完成待结果
      ├─ 拟录取待确认 ──(确认/自动确认)──→ 已确认录取
      │                 └─(逾期/放弃)──→ 未录取待补录
      └─ 未录取待补录
            → 补录中（第2轮 / 第3轮）
                ├─→ 已确认录取
                └─→ 待调剂
                      → 调剂录取（室内 / 跨室 / 约谈安置）
                      └─→ 最终未录取
已确认录取 / 调剂录取
  → 公示中 ──(无异议)──→ 正式入组
```

要点：已录取的学生不再进入后续补录 / 调剂；每个"未录取"出口都通向下一条兜底路径，直到统筹调剂的约谈安置为止。本届总名额略多于学生数，正常应几乎全员入组，"最终未录取"仅为极少数不服从调剂者。

## 八、非功能需求

- **并发与性能**：全量约 380 名学生，填报 / 确认都是集中硬窗口（如 08:00—12:00），可能全员同时在线。按峰值 \~400 并发设计、留 2 倍余量（\~800）。规模不大，单实例 + 数据库事务即可稳定支撑，关键操作响应及时、名额扣减不出错。
- **时间窗口控制**：以服务器时间为准，自动开放 / 关闭各阶段；客户端倒计时仅作提示，最终以服务端校验为准，防改本地时间作弊。
- **权限与数据隔离**：学生只见自己；导师只见本室相关；管理员全局。接口层做鉴权，防越权访问他人数据。
- **数据一致性**：名额相关操作全部事务化，任意时刻不超额；录取 / 递补 / 调剂有可核对的流水。
- **审计与防篡改**：评分、名单、录取、调剂、公示全程留痕；已生效结果锁定，改判走管理员留痕操作。
- **通知可靠性**：站内信必达；钉钉推送失败要重试 / 记录，关键截止不因推送失败而漏提醒。
- **可用性与容错**：关键窗口期保证稳定；提交类操作幂等，防重复提交、断线重试导致脏数据。
- **数据导出与备份**：各阶段名单一键导出 Excel；数据定期备份，可恢复。
- **易用性**：学生端流程清晰、移动端浏览器也能正常填报；管理端信息密度高、批量操作顺手。

## 九、技术选型建议

以"网页版 + 系统内账号 + 尽快能跑起来"为目标，推荐一套全 TypeScript 技术栈，前后端一门语言、迭代快：

| 层    | 推荐                                     | 说明                           |
| ---- | -------------------------------------- | ---------------------------- |
| 前端   | React + TypeScript + Ant Design + Vite | 表格 / 表单 / 后台管理组件成熟，适合数据密集型系统 |
| 后端   | Node.js + NestJS（TypeScript）           | 结构化、模块化，适合多角色权限和复杂业务         |
| 数据库  | PostgreSQL（或 MySQL）                    | 事务强，名额扣减 / 一致性有保障            |
| ORM  | Prisma / TypeORM                       | 数据模型清晰、迁移方便                  |
| 通知集成 | 钉钉工作通知 API / 群机器人 webhook              | 定向推送 + 群播报                   |
| 部署   | Docker + Nginx                         | 一键部署，校内服务器即可跑                |

备选：若学校更习惯 Java 生态，可用 **Spring Boot + Vue 3 + Element Plus + MySQL**，同样成熟，只是前后端两门语言。这套选型是建议，不是锁定，可按你的偏好调整。

## 十、已定的设计决策（原开放问题）

以下 10 点已确认，作为开发依据：

1. **规模**：380 学生 / 届，7 实训室，每室 5 导师（共 35），每导师约 12 人 → 总容量约 420，比学生多约 10%。并发按峰值 \~400、留 2 倍余量设计。
2. **名额粒度**：两级——实训室总名额为硬上限（约 60），导师带教容量做分配（约 12）。内部调剂 = 在本室导师间重新安置。
3. **面试评分**：四维各 0–25、满分 100、默认等权（可配置）；2–3 评委取平均（可选去极值）；时间投入可先由学生填每周小时数。
4. **并列排名**：总分相同 → 逻辑思维 → 编程基础 → 学习态度 → 时间投入 → 学号升序。确定性、可复算，不抽签。
5. **多意向逾期**：视为放弃全部拟录取，释放其占用的所有名额。
6. **递补 / 调剂面试**：递补直接生效并通知（不再单独确认），已在别处确认者跳过顺延；跨室调剂不再面试，按原面试总分 + 调剂意愿统筹。
7. **开放日 / 宣讲**：v1 纯信息展示，预约 / 报名 / 签到不做。
8. **公示异议**：学院管理员受理，公示结束后 24 小时内处理并站内信 + 钉钉反馈；成立则留痕改判、受影响部分重新公示。
9. **通知渠道**：站内信 + 钉钉。定向个人通知走钉钉工作通知，群播报可用群机器人 webhook。
10. **初始密码**：固定前缀 + 学号后 6 位（每人不同），首次登录强制改密；导师用工号同理。
